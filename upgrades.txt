2. The really important part: Digital Twin
Don't make a beautiful campus model that is just a background.
Make the campus robotically meaningful.
Every important object should have metadata.
For example:
Block_37
 ├── type: academic_building
 ├── floors: 5
 ├── accessible: true
 ├── entrances: 4
 ├── elevators: 2
 ├── rooms: [...]
 ├── navigation_nodes: [...]
 └── restricted_zones: [...]
Central Library:
Central_Library
 ├── type: library
 ├── building: Block_37
 ├── opening_status: dynamic
 ├── entrances
 ├── stairs
 ├── elevators
 ├── navigation_points
 └── semantic_zones
This is what turns it into a Digital Twin, rather than a 3D model.
The official LPU library information identifies the Central Library as being in Block 37, which is exactly the type of real-world semantic information we should encode into the simulation.

I'd give the agent a master specification, not a simple prompt like "create LPU in Gazebo."
Use this:
MASTER AI AGENT PROMPT
LPU Autonomous Robotics Digital Twin — Gazebo Simulation
You are a senior robotics simulation architect, ROS 2 engineer, Gazebo developer, AI/ML engineer, 3D environment designer, backend engineer and UI/UX engineer.
Your task is to build a production-quality research-grade LPU Autonomous Robotics Digital Twin using Gazebo + ROS 2.

The objective is NOT to create a static 3D campus.

The objective is to create a complete robotic simulation platform in which an autonomous robot can perceive, localize, navigate, reason, interact, execute missions, experience failures, recover from failures and communicate with centralized AI infrastructure.
